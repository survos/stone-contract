# Stone contract

`survos/stone-contract` is a PHP data contract for cemetery evidence shared by
MemorialAtlas and StoneStory. It contains immutable, JSON-serializable values.
It does not load folios, generate image URLs, run OCR, correct images or resolve people.

Status: initial contract, not yet published or wired into either application's reader.
The current MemorialAtlas OCR viewer remains an application component.

## Identity across cemetery folios

StoneStory is the cemetery presentation of the `fotostory` application. Its
`stonestory` folio set selects collections tagged `gravestone` and `cemetery`.
A folio is a source collection, not a cemetery: a collection can cover several
cemeteries, and several collections can describe the same cemetery.

`RecordReference` identifies a row by `(folioCode, coreCode, localId)`. Retain
source IDs as strings, including leading zeros. Never join by localId alone,
a person's name, an image URL or a cemetery label.

`PageReference` identifies imagery belonging to that row, using the existing
`PageDto` fields `seq` (one-based) and `pageIndex` (zero-based). It optionally
retains `mediaId`. A page is not a new `page` core or a second object record.
References follow the published page numbering; producers must preserve it.

The `StoneEvidence` envelope distinguishes a physical `marker`, a source
`burialRecord` and an unclassified `capture`. An Arlington burial record must
not become a physical marker merely because it has a photograph. Cemetery
membership uses reviewed `Core::PLACE` references. An empty cemetery list means
unassigned; it must not be replaced by the folio's name or inferred from camera GPS.
When a source has only a cemetery label, keep that label in its existing DTO;
do not fabricate a place ID to populate this contract.

## Existing contracts remain authoritative

| Existing representation | Mapping |
| --- | --- |
| Folio object/person/place rows | `RecordReference`; use `Core` constants |
| `PageDto` / published page row | `PageReference`, with the owning record |
| `PageDto.url`, `sourceUrl`, width and height | Resolve a durable raster into `ImageFrame`; preserve original provenance in the page |
| `PageDto.text` | Optional searchable projection of a selected OCR reading, not all runs concatenated |
| `PageDto.layout` | Candidate storage for the versioned evidence payload through an explicit adapter; do not overwrite an existing layout dialect |
| `BurialRecordDto` | Continues to own interment, section, grave and source burial fields |
| `PersonDto` | Continues to own person names and partial life dates |
| Folio `mentionsPerson` | A stone mentions a source-scoped person; not proof of burial |
| Folio `recordsPerson` | A source burial record documents a person |
| Folio `sameGrave` | Existing source-supported association, not inferred kinship |
| FTM/Yente identities | Resolved by the existing people service; never copied into a new local person database |

No new person, cemetery or burial schema is introduced here. Incomplete dates
retain their existing precision. OCR output is evidence, not a verified identity
or an instruction to create a burial or family relationship. Reference PENMAN
annotations remain separate from machine readings and evaluation inputs.

## OCR and image frames

An `OcrReading` is one provider run, with an immutable run ID, provider, optional
model and receipt location, exact plain text, and lines in provider reading order.
A line has a stable ID within that reading, optional polygon and optional
confidence. Missing geometry stays absent. Confidence is a provider score,
not measured accuracy or a human review decision. Human corrections should be
stored as separate evidence; never replace the machine reading in place.

Each reading embeds its `ImageFrame`: the exact, EXIF-oriented raster that defines
the coordinate system, its immutable ID, durable source, dimensions and optional
SHA-256. Coordinates are pixels from the top-left, with x increasing right and y
down. Edge coordinates may equal width or height. Boxes can be quadrilaterals;
do not flatten them to axis-aligned rectangles.

A display may uniformly resize that frame using the `thumb` or `detail` preset.
An SVG viewBox using the frame dimensions then keeps polygons aligned. Cropping,
rotation, perspective correction and stretching require a new frame or an
explicit coordinate mapping. A signed delivery URL is generated by the host;
it is not the durable source or frame identity. Do not serialize credentials or
expiring signed URLs into the contract. These DTOs do not enforce URL policy.

A `PerspectiveCorrection` records the parent frame ID and four source corners
in top-left, top-right, bottom-right, bottom-left order. The corrected frame's
width and height define the destination rectangle. Preserve the original raster.
Before computing the homography, the processor must resolve the parent, verify
that it belongs to the same source page, verify corners against its dimensions,
and check the declared corner orientation. Constructor validation rejects crossed
or degenerate quadrilaterals but cannot validate an unresolved parent.

The PHP OpenCV processor can use those corners to produce the derivative. The
contract does not depend on an OpenCV extension. Rerun OCR on the corrected
frame, or explicitly transform existing polygons with the same homography.
Never attach original-frame polygons directly to the corrected image. A planar
correction does not recover hidden or unreadable lettering.

## Example

```php
use Survos\DataContracts\Vocabulary\Core;
use Survos\StoneContract\{RecordReference, PageReference, ImageFrame,
    PixelPoint, OcrLine, OcrReading, StoneEvidence, RecordKind};

// Illustrative identifiers, not a claim that this row is published in mus/rapp.
$record = new RecordReference('mus/rapp', Core::OBJECT, '111');
$page = new PageReference($record, seq: 1, pageIndex: 0);
$frame = new ImageFrame('photo-119-original-v1', $page,
    's3://archive/originals/photo-119.jpg', width: 4000, height: 2252);
$line = new OcrLine('line-1', 'JOHN ROBERT', [
    new PixelPoint(977.05, 874.98), new PixelPoint(2492.12, 852.34),
    new PixelPoint(2495.62, 1087.92), new PixelPoint(980.54, 1110.56),
], confidence: 0.99394);
$reading = new OcrReading('ocr-run-1', $frame, 'imagor',
    'JOHN ROBERT', [$line], model: 'tiny');
$evidence = new StoneEvidence($record, RecordKind::Marker, [], [$reading]);
$json = json_encode($evidence, JSON_THROW_ON_ERROR | JSON_PRETTY_PRINT);
```

## Consumer adapters

MemorialAtlas must receive an explicit export mapping from its database item,
media and cemetery IDs to folio references. `item.id = 111` does not imply
`mus/rapp:obj:111`. Import manifests establish the mapping. Its current Imagor
receipt supplies `raw.width`, `raw.height`, `raw.regions[].box`, `text`, `score`
and `coordinate_space`. Accept the supported coordinate space explicitly;
convert each provider point pair to `PixelPoint` without rounding.

StoneStory resolves the selected folio and owning row before loading evidence.
Preserve multiple readings, including tiny/small comparisons. Legacy pages with
only text render text without boxes; pages without OCR remain viewable. Snapshot
readers stay read-only. Store new processing receipts through the existing
producer/enrichment pipeline and publish a new snapshot.

`survos/stone-bundle` can later own the Twig/Stimulus viewer and adapters. Keep
Doctrine entities, site routes, host selection and image delivery credentials in
the consuming applications. No `survos/stone` processing library is required by
this contract; add one when shared processing behavior warrants it.

## Validation and versioning

The envelope emits `schemaVersion: "1.0"`. Consumers must reject unsupported
major versions and hydrate through constructors to retain validation. This
initial package provides typed construction and JSON export, not an untrusted
JSON parser or a database migration. Null optional values are omitted; empty
lists and empty OCR text remain explicit. Changes to coordinate meaning or
identity require a new major contract version.

Run `composer test` after installing package dependencies. In the monorepo:

```sh
php vendor/bin/phpunit --no-configuration \
  --bootstrap lib/stone-contract/tests/bootstrap.php lib/stone-contract/tests
```
